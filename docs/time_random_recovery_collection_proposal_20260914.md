# 条件付きランダム外乱による復帰データ収集案

## 状態と判断

2026-09-15にユーザーが本方針の収集から検証までを承認し、実装・WSLテスト・実走・原本照合・教師生成を完了した。修正版は独立2run・6復帰イベント、学習273件＋検証243件＝516教師。以下は提案時の記録で、確定結果は[収集・検証記録](time_random_recovery_collection_20260915.md)を参照する。未使用runの自動追加やモデル再学習は本計画に含めない。

ユーザー提案は「一定時間ごとにランダムな外乱を入れ、基準経路からずれた状態から戻る区間を抽出する」。1周中の復帰機会を増やす方針は妥当で、現在の1周1回方式より収集効率を上げられる可能性がある。増加量と復帰成功率は未測定。進行中だった左右2runは完走・転送・監査を完了し、復帰教師185件を生成した。[結果](time_recovery_phase_expansion_20260914.md)。その後の方式についてユーザーの選択を待っている。本書は検討案であり、反復外乱の実装・走行は未実施。

教師PPが通常走行している間に、実際の車両への操舵指令へ有限の外乱を加える。解除後は教師PPによる復帰を実測し、その時点のCamera・LiDAR・ego履歴と将来3秒の実測位置を対応させる。モデルによる復帰性能の評価とは別の収集作業である。

## 実行方式

1. シミュレーション時刻で次の候補時刻を決める。候補時刻になった後、位置・姿勢・速度が既存の開始条件へ収まり、正常なセンサ入力・操舵余裕・停止領域の確認が成立するまで待つ。成立しない候補は見送り、次の外乱を重ねない。
2. 開始位置、左右、振幅、持続時間の候補を、記録したseedから生成する。最初の試験では左右と開始時刻だけを変え、現行の振幅・持続時間・状態上限を保つ。効果が弱いという理由で自動増幅・延長しない。
3. 既存の状態目標、横ずれ・向き・速度の上限、時間上限で外乱を解除する。停止領域やセンサ等の監視は制御発行後段に維持する。
4. 外乱ゼロの教師指令が実際に発行された時刻から復帰を記録する。復帰確認のため、位置・向きが許容範囲へ戻った状態の連続維持を確認する。横ずれの毎フレーム単調減少は条件にしない。
5. 復帰区間、将来教師3秒分、安定走行期間を確保してから次の外乱を許可する。規定時間内に復帰確認できない場合は反復を打ち切って分類し、元の停止監視を維持する。

周期は外乱を必ず投入する締切ではなく、次の候補を調べる間隔として使う。候補時刻にばらつきを持たせ、同じコース位置ばかりに偏ることを避ける。左右の採用数も記録する。

当初の試験案は少数run・1周あたり最大3回。固定位置計画の未使用run IDを別条件で再利用せず、独立した計画・seed・出力rootで管理する。投入回数上限に達しなくても1周と将来末尾・停止を収録する。目標速度5km/h、通常RViz、最大1800秒、同時走行1台という既存条件を維持する。

## 必要な実装変更

| 対象 | 現在の確認結果 | 変更内容 |
| --- | --- | --- |
| `time_steering_pulse_v1.py` | `waiting`→外乱→解除→復帰→`complete`の1回分 | 既存1回分を包む有限スケジューラを追加。安定確認、候補時刻、seed、最大イベント数、見送り理由を管理 |
| `time_recovery_collector_node.py` | 発行成功時だけ状態を確定し、外乱の要求値・実効値を記録 | イベントIDを付け、投入・解除・最初の外乱ゼロ発行・復帰確認を実際の発行時刻へ対応させる |
| `time_recovery_collection_v1.py` | 非教師区間・欠損・後続の外乱を将来マスクで排除 | バージョン付きイベント形式を検証し、同一イベントの採用区間と根拠を保存 |
| `analyze_pulse.py`、復帰集計 | 最初の解除1回を基準に集計 | 全イベントを個別集計し、イベントの重複・取り違えを防止 |

現在の正常実走guideはコース進行約60〜135mを対象としている。全周の任意位置へ広げるには、既存正常実走の観測からguideを拡張して範囲・周回境界を検証する必要がある。初回は検証済み範囲に候補を制限する。ガイド外で姿勢差をゼロと仮定しない。

## 自動抽出条件

- 対象は外乱解除後150ms以降。カメラ時刻から将来3秒すべてに、連続した実測位置と外乱ゼロの教師制御が必要。次の外乱・停止介入・欠損をまたぐanchorは不採用。
- 0.1秒間隔の30点、XYは車体座標m。画像・LiDAR・ego履歴は実際にずれた状態の観測を使い、教師だけの平行移動や未来の外挿はしない。
- 入力の過去履歴に外乱中の実観測が含まれること自体は除外理由にしない。推論入力の因果性とセンサ品質は既存監査で確認する。
- 復帰後まで観測して成功・未復帰・監視停止を分類する。未復帰や監視停止の記録も保存し、成功教師へ自動混入させない。
- 1回の復帰について、位置ずれ、向きずれ、コース位置、曲率、左右、速度、復帰所要時間、有効anchor数を保存する。大きくずれた直後の有効な観測も残す。
- 採用・不採用のイベント一覧とanchor IDを出力し、同じrawから同じ教師を再生成できるようにする。代表イベントを軌跡とセンサで確認する。

## データ分割と試験

分割は収集run単位で事前に固定する。同じ周回のイベントをtrainとvalidationへ分散させない。1周に3回の復帰があっても、独立3runとは数えない。既存の正常走行データと統合する際は、復帰フレームの比率・左右・コーナー位置の偏りを併記する。従来のtest4runと予約r48/r49を使わない。

実装する場合の必要テストは、seed再現、イベント上限、未復帰時の再投入禁止、発行失敗時の状態不確定、時刻逆行、将来3秒への次外乱混入、イベント境界・同時刻矛盾、欠損・範囲外guideの拒否、既存単発形式の互換性。Windowsでcommit後に同期し、native WSLのworktree lock下で既存pytestと新規テストを実施する。

少数runの成否はイベント数だけで判定しない。未復帰・停止の有無、実際の位置と向きの分布、有効教師数、正常入力との対応、保存・再抽出の再現性を確認する。教師の増加だけでは提案モデルの完走・復帰改善を証明しない。
