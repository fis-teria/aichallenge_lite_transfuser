# 時間基準モデル・学習構成の静的確認（2026-09-11）

ユーザー指示によりSSD到着まで学習・大容量転送は保留。コード、設定、既存試験報告を読み、実装変更・学習・評価実行は行っていない。以下の原因候補の寄与率は未測定。

## 結論

Camera + LiDAR + ego履歴の融合を全面的に作り直す根拠はない。一方、現行V4-10をそのまま未来3秒の学習へ使うことはできない。先に教師・モデル出力・損失・実行時の時間契約を統一する必要がある。

## 優先度が高い確認事項

1. **距離基準と時間基準の契約が未統一（確定）**
   - `models/spatial_path_ten_v4.py:17` は72値を36個のXY座標へ変換する距離基準ヘッド。
   - `training/spatial_ten_v4.py:29` は `LONG_GRID[:36]`、損失と評価も距離帯域。
   - 旧 `models/full_control_lite_v3.py:73` は15点以外を拒否。`data/dataset_view_v3.py:621` は未来配列の先頭N点を取る。既存0.1秒教師で15点なら1.5秒であり3秒ではない。
   - `runtime/spatial_ten_shadow_v4.py:55` は距離グリッドとモデル種別を固定検証する。
   - 対応案：0.1〜3.0秒、30点、観測時刻のbase_link座標という契約を明記。チェックポイントに時間配列・単位・座標系・前処理識別子を保存し、runtimeが検証する。距離ヘッドの出力行を時間点として再利用せず、新ヘッドにする。表現部の継承は比較候補。

2. **V4は位置のみで、速度・停止の学習がない（確定）**
   - `models/spatial_path_diagnostic_v4.py:25-29` は制御・行動ヘッドを無効にし、旧軌道・速度ヘッドを除去。
   - `training/spatial_long_v4.py` の `band_loss` は観測XYのSmooth L1のみ。隣接点の速度・加速度の整合性を直接学習しない。
   - 無制約の座標出力は折返しを禁止しない。ただしヘッドだけが既存折返しの原因と確定したわけではない。
   - 旧V3には増分累積軌道ヘッドと速度ヘッド、任意のplan_consistency損失がある。ただし累積和だけで曲率・加速度の実現可能性は保証しない。
   - 対応案：時間XY・速度・停止を明示して設計。位置差分からの速度と速度出力の整合性を検証する。区間平均速度と時点速度、横速度を含む速度ノルムと前後速度の違いを揃え、既存整合損失を無批判に流用しない。停止を出力契約に用意するだけでは学習されない（V3のstop_logitは任意欄だがFullControlLiteV3は出力していない）。

3. **旧学習器は新コーパス向けの一般学習設定ではない（確定）**
   - `training/spatial_ten_v4.py:31,113,159` は2epoch、validation64件、既存checkpointと親データを固定した追加学習実験。
   - これは過去実験の欠陥という意味ではないが、新20周の学習・モデル選択へそのまま使えない。2epochで収束済みとも未収束とも断定できない。
   - 対応案：run単位splitを先に固定し、速度別・コーナー別・発進別・予測時間別に評価。検証損失の推移でcheckpointを選び、testを調整に使わない。初回は有限epoch/時間予算を明記する。

4. **新20周を単純結合すると速度・場面の重みが偏る（観測からの判断）**
   - このタスクで確認済みのbag件数は5km/h設定39,060画像、8km/h設定22,143画像。同じ10周でも低速側が約64%になる。
   - 同じ経路・初期条件の再起動は保存runを独立にするが、未知条件の多様性を保証しない。
   - 対応案：run/速度/場面ごとの件数と有効未来率を報告し、目的に合わせてサンプル重みを決める。既存normal/recoveryや指令由来proxy教師を無区別に混ぜない。評価の射程は同一コース再現条件に限定する。

5. **教師の操作指令履歴への依存は閉ループで分布が変わる（構造は確定、影響は未測定）**
   - `data/spatial_diagnostic_inputs_v4.py` は過去のnominal/final指令を入力し、`models/encoders/ego_history.py` は指令GRUを融合する。
   - 過去時刻のみを使う制約があるため、これ自体を未来教師リークとは呼ばない。しかし収集時のPure Pursuit指令と、モデル走行時の自己出力・Safety介入後指令は同じ分布とは限らない。
   - 対応案：将来の学習比較として指令履歴あり/なしを比較し、同一run splitで入力依存を測る。未来教師・正解経路を推論入力に追加して解決しない。

6. **時間情報を保存していても、現特徴抽出器は時間差を使っていない（確定）**
   - `data/spatial_diagnostic_inputs_v4.py` はsensor_dtを保存し、未融合であることを明記。
   - `models/temporal/gru.py` の履歴選択は前の行を順に選択。`epoch_keys` は0.2秒まで同一履歴に許容するため、行数だけでは常に0.1秒間隔を保証しない。
   - 対応案：canonicalで欠落を明示した固定時間グリッドを使い、学習とruntimeの欠落・padding規則を一致させる。必要ならdtを入力するが、追加効果は測定前には主張しない。

## 教師生成時に合わせて見直す事項

- `data/dataset_view_v3.py:846` の既存FullControlデータ選択は現在の有効指令を必須にする。位置/速度のみの教師として使える行も落ち得るため、時間モデルの必要条件から選択を設計する。
- 旧1.5秒のcommanded-motion stationary filterを新3秒契約へそのまま継承しない。正常停止、発進待ち、収集終了介入、未観測未来を区別する。
- 収集終了ブレーキと、それを未来3秒に含むアンカーは通常巡航教師から除外または介入として分離する。途中欠損を停止教師へ置換しない。
- 距離基準の最低進行距離・stationary-jitter除外を時間基準教師へ流用しない。既存AWSIM位置精度を受け入れる方針は維持し、速度/姿勢との整合性を確認する。

## 容量・速度に関する注意点

- `training/spatial_ten_v4.py:35` はWSL backing volumeをD:とハードコード。新SSDへ移行後は実際にVHDを置いた物理ボリュームを監視する必要がある。
- on-demand + CPU LRU方式は維持候補。SSD追加だけを理由に大量float32入力キャッシュへ戻さない。
- 過去試験報告 `docs/v4_10_tracking_trial_20260910.md:84-88` では約10%の制御周期が古いplanによるブレーキ。学習精度の改善だけでこの遅延が解消するとは言えない。再開後は推論・前処理・配送の遅延を分けて計測する。
- `FullControlLiteV3` はResNet18をpretrained=Falseで構築するが、V4はcheckpointから継承するため「今回カメラを完全にゼロから学習した」とは断定しない。事前学習有無やBatchNormの小microbatch影響は比較候補であり、現時点の確定原因ではない。

## 保全する良い構成

入力とteacherの分離、過去指令の因果制約、run split重複チェック、観測mask、勾配クリップ、非有限値チェック、checkpoint識別、Safety Supervisorは維持する。学習モデルを大型化する前に上記契約と評価を整える。

## 検証範囲

静的コード・設定・既存報告の確認のみ。学習、pytest、WSL評価、AWSIM、新データ転送は実行していない。性能改善量、指令依存の強さ、収束性、全新bagの教師品質は未測定。次の実装・学習はユーザーの保留解除後に扱う。
