# 時間基準E2E修正案 — Astra Proレビュー用

## 0. 判断対象と現状

目的はCamera + 2D LiDAR + egoから、追従可能な時間軌道を学習する提案モデルの構築。
現行V4-10は距離基準36点、旧V3は時間基準15点。新TimePathV1のモデル・損失だけ実装済み。
実装commit bec20369068c1bf25bc77d702cd0d5c12f187ad8、検証報告commit 1af7505ccb580163e329df8bcaaba2d11a5f6c36。
学習・大容量転送は新SSD導入まで保留。今回のレビューは実装済みcoreと以下の未実装計画が対象。
従来モデルの訓練を無効とする主張ではなく、時間基準移行時の整合性と閉ループ能力を評価してほしい。

## 1. 教師・時刻・座標の統一（必須、未実装）

提案追加先: data/time_view_v1.py、contracts/time_plan_v1.py。
- t_obsを基準としてt=0.1..3.0秒の30点。XYはbase_link@t_obs、x前方/y左方、m。
- 時刻は整数nsで比較し、float秒はモデル契約・表示用に変換する。
- raw収集から既存canonical converterを再利用するが、既存の変換がこの座標契約と一致することを合成軌跡と少量の実データで確認する。
- canonicalのgrid時刻とカメラ取得時刻の差を記録。教師の原点・ego補間・runtimeの観測アンカーを同一にする。どちらをt_obsに選ぶかはレビューの判断対象（推奨: 実カメラ取得時刻を基準とし、履歴スロット時刻を別管理）。単に時刻ラベルを書き換えない。
- 未来位置は観測から補間し、外挿しない。同じrun/clock epoch内、補間両端の有無・gap・有限値を確認する。
- 既存camera40ms、LiDAR30ms、補間50msの閾値は既存値として記録し、自動的に緩めない。サンプリング周期と閾値の意味を確認し、除外率を報告する。
- [B,30,2] xy_m、[B,30] future_mask、[30] time_secを明示。未観測未来はmask=False。停止中の観測済み同一位置は有効。
- 収集終了ブレーキ開始t_bに対して、アンカーt_obsの対象未来がt_b以降を含む場合、初版はそのアンカー全体を巡航学習から除外する。ブレーキ後も除外。境界が曖昧な例は別集計。通常の環境要因による停止とは区別する。
- 教師操作指令の欠損だけで、位置教師が有効なアンカーを捨てない。利用する各出力に独立したmask/provenanceを持たせる。
- 距離基準の最低進行距離・低速除外、旧1.5秒stationary filterをそのまま流用しない。
受入条件: 直進/旋回/停止/時刻reset/欠損/介入境界の合成テスト。全除外理由とrun別の1/2/3秒有効件数を出力。

## 2. 入力履歴の統一（必須、未実装）

提案追加先: data/time_history_v1.py。runtimeとofflineで同じ純粋関数を利用。
- camera/LiDAR4スロット、ego/command10スロット、間隔0.1秒を初期案とする。
- 直前N行ではなく、時刻からスロットを選び、穴を詰めない。run/segment/clock resetを跨がない。
- 推論に利用可能だった観測・指令だけを選ぶ。header時刻だけでなく到着/利用可能時刻も扱う。bag受信時刻が実処理の利用可能時刻を完全に復元するとは主張しない。
- 取得時刻のずれ、選択誤差、欠落maskを保存。未来教師の補間条件と推論入力の因果条件を混同しない。
- 前処理は既存の画像RGB正規化、LiDAR range+validityを共通化。750点・角度範囲・センサ座標/取付姿勢はbagの仕様と照合。点数が同じだけでは互換と判定しない。
- 初版は固定時間グリッド+mask方式。dtを特徴に追加する案は別比較とし、効果未測定のまま必須にはしない。
受入条件: 同じ観測イベント列に対しoffline/runtime入力tensorが一致。欠落・遅着・重複stamp・初期paddingを試験。

## 3. モデルcoreの扱い（部分実装）

実装済み: models/time_path_v1.py。既存fusionからGRUCellへ、XY増分を30回累積。
L1位置損失は有効点をアンカー内平均し、有効アンカー平均する。未来欠損を算術前にゼロ化。
interval_speedは ||p_i-p_(i-1)||/0.1。区間の弦長速度ノルムであり、符号付き前後速度でも瞬間速度でもない。

レビュー必須の未解決点:
- 30段の自己回帰で誤差蓄積・勾配不安定が増えないか。累積和だけで滑らかさや物理制約は保証しない。
- goal/route入力がない。分岐・複数意図には原理的に曖昧さがある。初回の同一固定コース再現を越える主張はしない。将来追加する場合は運用中に入手可能なroute意図に限り、未来正解経路を入力しない。
- 低速の位置ノイズを0.1秒で微分すると速度が不安定になり得る。区間集約・速度教師との比較を検討する。位置精度を上げる要求で作業を止めない。
- use_command_historyは現在単なる属性でstate_dictに含まれない。必ず将来checkpointの入力構成に保存し復元検証する。
- time_contract helperはcheckpoint loaderではない。型を含む厳格schema、時間グリッド、前処理ID、モデル構成の検証を別実装する。
- FullControlLiteV3の15点制約は内部で未使用の旧headに由来し、現在のcoreは構築後にheadを除去する。30点をそのkwargsに渡すと失敗する。新モデル設定は内部の旧trajectory_stepsを公開せず、互換backboneと新decoderの設定を分離する。
受入条件: 既存5件に加え、metadata欠落/型違い/距離checkpoint誤投入/command設定違いを拒否するテスト。

## 4. 速度・停止と追加損失（選択的比較、未実装）

B0: 現waypoint-only core + 外部で区間速度を導出する基準。これは停止確率を学習しない。
B1: 同一split・seed・提示数で、独立した速度出力を追加。区間弦長と比較するなら教師も同じ意味に揃える。
B2: B1に弱い速度整合性lossを追加。mとm/sの重みを明記。signed v_longとの誤比較を禁止。
B3: 必要なら加速度急変の正則化。正常旋回・発進停止の過平滑化を評価し、位置lossを隠さない。
停止確率: 停止理由と有効な停止ラベルを定義した後の独立段階。停止継続時間/速度閾値はレビューで決め、収集終了介入を正例にしない。
B0で停止速度に近い結果が出ても、障害物を認識して止まる能力を得たとは扱わない。
受入条件: baselineより場面別評価と閉ループ成績が改善し、停止/発進/旋回を悪化させない。効果なしなら追加を採用しない。

## 5. 学習器・checkpoint・ストレージ（必須、未実装）

提案追加先: training/time_path_v1.py、configs/models/time_path_v1.yaml。
- V4-10学習器の親run固定/validation64固定/2epoch固定から切り離す。
- 初期化はscratchと既存表現継承を区別。継承はbackboneの許可キー/shape/有限値を検証し、ロード/除外一覧と元SHAを保存。距離headはロードしない。
- 学習対象run manifest、教師契約、前処理ID、モデル寸法、command履歴設定、optimizer、RNG、stepを保存。resumeと新規fine-tuneを区別。
- float32 + microbatch2/有効batch8を初期比較候補とし、小batch BatchNormと時系列相関の影響をレビュー。既存LR backbone1e-4/head1e-3は候補であり新モデルの最適値と主張しない。
- 全無効batchはoptimizer.stepを行わず集計。有限値/grad norm/有効点数/速度・場面別lossを記録。
- epochと時間の有限予算、評価予約時間を実行前に固定。今回レビューで学習は開始しない。
- on-demand+bounded CPU cache。SSD移行後、実際のVHD backing volumeと出力先の空き容量を監視。固定D:判定を設定化し、起動時に保存先との対応を検証する。
受入条件: 合成少量batchでforward/backward/checkpoint保存再読込/中断再開が一致。実データ学習はSSD移行後。

## 6. splitとオフライン評価（必須、未実装）

収集20run: 5km/h設定10、8km/h設定10。画像39,060/22,143、LiDAR82,032/46,504。
これはrawの件数。teacher採用数ではない。設定速度と実測速度は区別する。
- 提案split: 各速度train6/validation2/test2。ただし再起動以外の条件がほぼ同じなので未知条件汎化の評価ではない。ID割当を学習前に固定しtestを調整に使わない。
- 既存normal/recoveryと新20runは出所別に管理。公開指令proxyは初版の実測位置教師へ混ぜない。
- 全frameで低速側約64%。初回は速度帯均等サンプリング候補。採用後の分布を再計算し、自然分布評価と均等評価を両方出す。多数の隣接frameを独立試行と数えない。
- 0.5/1/2/3秒の位置誤差、横/縦誤差、速度誤差（定義を揃える）、発進/停止/旋回、無効/棄却率を出す。
- 停止時の重複点を異常折返し扱いしない。曲率計算のゼロ長区間と低速ノイズを扱う。
- runごとの成績・最悪runを報告。良いframeだけ抜粋せず、支持率と分母を併記する。
受入条件: split交差ゼロ、history/futureのrun越境ゼロ、固定manifestで再現。

## 7. runtime・制御・閉ループ（必須、未実装）

提案追加先: runtime/time_path_v1.py、control/time_reference_v1.py。
- 型付き時間planとして読み込み、旧距離36点用adapterへの誤接続を拒否する。
- planの観測時刻と現在時刻の差を計測。消費済み時間を取り除き、残り軌道の座標を現在自車系に変換するには、その間の自己運動推定が必要。単にwaypoint indexをずらすだけにしない。
- 速度はまず時間軌道由来の参考値。停止距離、制御周期、車両制限、Supervisorと整合させる。低速の零長軌道では方位・曲率除算を行わない。
- 異常な折返し・曲率・NaN・古いplanは棄却/停止。黙って整形した軌道だけを評価せず、rawと採用結果を両方記録する。
- 前回のstale planブレーキ（約10%）は推論/前処理/配送/周期を分けて計測。TTLを緩めて隠さない。
- 全周評価はrun/scenario単位。発進、コーナー、初期位置・姿勢ずれ、停止を段階的に含め、教師と同一の経路だけで十分としない。
受入条件: 合成直進/旋回/停止と遅延注入試験、既存Supervisorの保持、その後AWSIM走行。新モデルの走行性能は現時点で未検証。

## 8. 推奨実装順序・判定

P0: 1と2と3のmetadata/decoderレビュー → 教師・入力の整合性を確定。
P1: 5と6 → SSD移行後、B0のみ有限予算で学習。
P2: 7 → 同一条件で旧モデル/教師コントローラと比較。
P3: 4と指令履歴ablation → 失敗場面の復帰データを追加して再評価。
重大問題が出た段階で該当設計を修正し、試験で確認する。レビュー承認だけを性能保証にしない。
