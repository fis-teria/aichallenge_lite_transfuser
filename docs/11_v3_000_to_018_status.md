# V3-000 through V3-018 implementation status

## Reached boundary

This checkout implements the task-manifest sequence through `V3-018`, the current-control
auxiliary needed to train the initial full-control model. `V3-019` and later calibration,
projection, authority, evaluation, export, and closed-loop tasks are not implemented.

The supported initial contract is:

- Camera and native-order 2D LiDAR history: 4 observations
- ego-state and command history: 10 observations
- trajectory candidates: 1
- dense trajectory points: 15
- outputs: ego-frame XY trajectory in metres, non-negative speed profile in m/s, and current
  steering in rad, speed in m/s, and acceleration in m/s^2
- current-control teacher priority: nominal command, then explicitly tagged `final_fallback`
- checkpoint resume identity: Dataset, split, view, and model contract hashes

## Training commands

First validate without writing a run:

```bash
tools/with_wsl_training_lock.sh .venv/bin/aic-e2e train \
  --config configs/models/full_control_lite_v3.yaml \
  --dataset-root /absolute/path/to/dataset_v3 \
  --split-manifest /absolute/path/to/split_manifest.json \
  --view-config configs/data/view_temporal_v3.yaml \
  --output /absolute/path/to/runs/full_control_lite_v3 \
  --dry-run
```

Remove `--dry-run` to train. Add `--resume` to continue `last.pt` in the same output directory.
The trainer writes `last.pt` atomically and records the effective identity and last loss row in
`run_manifest.json`. Raw and weighted losses are separate. A NaN loss terminates immediately.

The default config targets an 8 GB GPU with micro-batch 2 and gradient accumulation 8. The
current lightweight trainer stores the accumulation setting as configuration guidance; one
optimizer step is currently performed per materialized micro-batch. Do not infer an effective
batch size of 16 until accumulation is implemented and verified.

## Required gates and limitations

- Split membership is run/scenario grouped; frame-random split is not used.
- Temporal windows are left-padded at a clock-epoch boundary and never cross it.
- Full-control training requires a valid nominal or final command label at the anchor.
- If an ego feature configured as an inference input is missing at the current observation, the
  anchor is excluded rather than zero-filled as valid.
- The trajectory regression gate is implemented and must pass before promoting a control-auxiliary
  checkpoint. This task did not run a real validation set or promote a checkpoint.
- The trajectory-only ROS profile has no nominal-control publisher and validates checkpoint,
  runtime-manifest, and model-contract hashes.
- Safety P0 rejects zero-valid-front-beam scans, invalid/future/stale timestamps, and late command
  proposals; speed and command validity are bounded.

## Verification boundary

Unit, negative, one-epoch synthetic Dataset V3 training, checkpoint, and resume tests are automated.
No real Dataset V3 full training, ROS 2 launch, or AWSIM closed-loop result is implied by those tests.
ROS 2 and AWSIM execution is restricted to `graneple@192.168.3.10` for this workstream and must be
reported separately with the actual command and result.
