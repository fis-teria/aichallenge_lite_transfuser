記事を分けて、変更と一緒に更新する

サイトをテーマ別記事へ分割。開発時の更新ルールと、更新漏れ・生成物のずれを検出する検査を追加しました。

公開 2026-09-27 更新 2026-09-27 運用変更

トップは全体の案内、詳しい情報は個別の記事へ

構成、技術スタック、検証記録、参考論文を、それぞれ独立したURLで読めるようにしました。サイドメニューは各分野への入口として維持します。

記事の種類に合わせた更新

  • 構成・技術スタック・今後の課題は、同じ記事を更新して現在の説明を保ちます。
  • 別の試験条件や新しい実測結果は、新しい検証記事にします。過去の失敗・限界は残します。
  • 参考論文は1本につき1記事。新たな手法との対応づけは、関係する記事からリンクします。

開発と記事更新を同じ作業に含める

モデル、入力契約、データ処理、制御、依存環境、起動方法、検証結果が変わったら、関連する本文と更新日を確認します。変更内容、検証した範囲、未確認事項、根拠を記事に反映します。

CIは変更差分に記事本文の更新があるかを検査します。読者向けの説明に影響しない変更は、その理由と対象ファイルを専用記録に残します。CIが記事の意味や実験結果を自動で執筆・判断する仕組みではありません。

公開までの流れ

記事を編集 → 一覧とHTMLを再生成 → リンク・記事メタデータ・更新対応を確認 → mainへ反映 → GitHub Pagesへ配信、という流れです。記事一覧・関連記事・更新履歴は共通のメタデータから生成します。

この変更はサイトの整理と更新運用に関するものです。追加の学習やAWSIM走行試験を実行した報告ではありません。
