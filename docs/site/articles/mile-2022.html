論文詳解・世界モデルと模倣2022

MILE：世界の状態を学び、方策と一緒に先を想像する

Anthony Hu、Gianluca Corrado、Nicolas Griffiths、Zak Murez、Corina Gurau、Hudson Yeo、Alex Kendall、Roberto Cipolla、Jamie Shotton

MILEは画像からそのまま操作を当てるだけでなく、履歴と確率的な状態を介して、画像・鳥瞰図・操作を一緒に学びます。観測で状態を更新する経路と、観測なしで未来を進める経路を持ちます。世界モデル、模倣方策、反復推論の役割を分け、CARLAでの成績を現行のwaypoint出力へ読み替えないように整理します。

確認日：2026-10-26、公式一次資料からの独立再執筆版。対象はModel-Based Imitation Learning for Urban Driving、arXiv v2（2022-11-03）の§3–6と関連評価、公式コード固定版c8b245c（2023-04-13）のREADME・model・transition・agent・評価設定です。初稿は2022-10-14、NeurIPS 2022。選択範囲の静的確認であり、全付録・証明・実験commit/重みの完全対応、著者コード実行、独立追試、導入・学習・走行は未実施です。

1. 画像の圧縮に、3Dと鳥瞰図の構造を入れる

入力は前方RGB、交差点で進む方向を示すroute map、車速です。画像特徴に深度の確率分布を予測し、camera内外パラメータを使って3Dへ持ち上げ、鳥瞰（BEV）へpoolしてから小さいベクトルへ圧縮します。ここでの深度は画像から学ぶ表現で、推論時に正解のBEV segmentationを与える構成ではありません。学習では特権情報を使うRL教師の操作とBEVラベルを利用します。§3

2. 観測によるposteriorと、未来へ進むprior

学習目的はELBOに基づき、画像の二乗誤差、操作のL1、BEVのcross-entropy、状態分布のKLに対応します。低い画像再構成誤差が、そのまま歩行者の安全や閉ループ成功を保証するものではありません。未来を想像するときは、予測操作を次の遷移へ渡すか、与えられた操作系列を使うかも区別します。

固定版transition.pyはactive_inference=Falseで初期化され、その分岐では渡された操作をpriorへ入れます。modelのimagine処理には、predict_actionに応じて方策予測と与えた操作を切り替える経路があります。論文図の予測操作と、全コード経路の入力が常に同じだとは扱いません。

3. 学習・評価の町と、Driving Scoreの意味

データはCARLAのTown01/03/04/06、4天候で収集した32時間・約2.9M frames。収集は25 Hz、系列モデルには5 Hzへ間引いて使います。学習条件は長さ12、batch 64、50,000 iterations、V100×8です。推論全体が5 Hz固定という意味や、必要GPUの最小構成を示す数字ではありません。§4

主評価は未学習のTown05の10 routesと4つの未学習天候で、3 runsの平均を報告します。比較には各方式の公開済み重みを使っており、全方式を同じ収集データで学び直した比較ではありません。Driving Score（DS）は経路達成と違反ペナルティを組み合わせる値で、成功episodeの割合ではありません。

4. 履歴を保持する推論と、観測なしの想像

表2　Table 3、同じCARLA評価でのdeployment方式
方式DS報告周波数 Hz状態の扱い
Reset state61.1 ± 3.26.2直近12観測から状態を再計算
Fully recurrent62.1 ± 0.543.0保持状態を新しい観測で更新
Recurrent + noise48.8 ± 1.843.0過去の潜在状態へノイズを加える診断

約7倍という値はこの推論方式の比較です。カメラから実際の操作適用までの期限保証や、任意のPCでの43 Hzを示す値ではありません。過去状態へのノイズで成績が低下する結果は、状態が使われている証拠ですが、どんな長さの履歴でも安定という証明ではありません。

deployment_forward()はlast_h / last_sampleを保持し、strideに応じて観測更新や想像の経路を選びます。agentは操作履歴を用意し、モデルのthrottle_brake / steeringを環境側へ渡します。公式READMEはCARLA 0.9.11を対象にしています。

原著の「走行の30%まで想像にしても性能を保つ」は、観測と想像を切り替える選択されたCARLA実験です。30%の任意センサ故障を許容できる意味ではありません。見えていない間の急な割込み、観測の戻り方、累積誤差は別に検証する必要があります。

5. 現行TimePathとの接続は、入力・出力・学習目的から設計する

公開main 5607db7のTimePathV1は1回のforward内でGRUにより30点の将来XYを出します。これだけでMILEの観測間の世界状態や生成モデルを持つとは言えません。現在の指令履歴、MILEの操作履歴、RAMの行動token、保持した制御経路も、型と役割を分けて扱います。

  • 適用候補：観測間の潜在状態と、操作に条件付けた予測を研究候補にする。MILEの直接操作出力をそのまま現行の主出力へ置き換える作業は行っていない。
  • 必要データ：時刻をそろえたRGB・camera較正・route・車速・適用操作と、学習用BEV教師。特権ラベルと推論時入力を分離し、run/scenario単位でtrain/testを分ける。
  • 再学習と資源：現行モデルへ再帰状態を足すなら損失・状態reset・長期履歴の扱いから変更が必要。画像再構成やBEV生成、状態保持のメモリ、全入力から指令までの遅延を測る。原著の8 V100を最小必要資源とはしない。
  • 必要検証：未知の町・路面・対象、欠損観測、状態の破損、reset忘れ、想像から観測への復帰を分けて比較する。オフライン誤差、閉ループ達成、接触、停止、計算期限を個別に記録する。

これらは未実装の研究候補です。学習・制御コード変更、MILEの実行・追試・学習・走行は行っていません。関連記事：E2E研究地図、World on Rails、FIVE-VLA、MPC / MPPI、NavSafeの閉ループ評価、調査範囲。
