E2E自動運転の全体像と比較の読み方

2018年後半から2026年までの代表研究を、学習境界・教師・時間・評価で整理する。

公開 2026-10-02 更新 2026-10-02 文献調査

E2E自動運転は「画像から直接操舵する一種類の方式」ではありません。学習する範囲、観測できる情報、出力の契約、評価環境が異なる研究群です。本稿は2018年10月2日から2026年10月2日までの代表例を、E2E Lite TransFuserで設計判断に使える分類へ整理します。全論文の網羅調査ではなく、比較条件を揃えるための入口です。

最終確認日：2026-10-02。論文の初回公開年と会議・誌面の発表年を区別します。企業の公開発表は技術動向の証拠として扱い、独立に再現された走行性能とは扱いません。

何を解く技術か

車両が次にどう動くかは、道路形状、障害物、他車の意図、自車状態、目的地の組合せで決まります。モジュール方式では認識・予測・計画・制御の間に人が定めた表現を渡します。E2Eでは、その一部または全体を最終的な運転目的に沿って学習します。重要なのは「ニューラルネットが一つか」よりも、「どの誤差がどこまで伝播し、どの部分が固定されるか」です。

たとえばTransFuserはセンサからwaypointまでを学習し、低レベル操作はPIDへ渡します。UniADは追跡、地図、運動予測、占有、計画という意味を持つ中間タスクを残して統合学習します。ChauffeurNetは認識済みの環境表現を入力とするため、raw sensorからの認識を含む方式とは境界が異なります。これらをすべて「完全なブラックボックス」と呼ぶと、監督信号と故障箇所を見失います。TransFuser §3、UniAD §3、ChauffeurNet

2018年から2026年への流れ

2018年後半から2020年：模倣の成功だけでなく、失敗状態を学習へ入れる方法が中心的な問題になりました。2018年12月公開のChauffeurNetは実演軌道を乱して望ましくない状態を合成し、回復を学ぶ方向を示します。2019年のBehavior Cloningの限界研究はデータ分布と動的物体への一般化を検証しました。Learning by Cheatingは特権情報を持つteacherから視覚studentへ段階的に知識を移します。なおConditional Imitation Learningの2017年初回公開・2018年5月会議は本稿の期間外で、経路指示を条件にする前史としてのみ参照します。ChauffeurNet、BCの限界、LBC

2021年：情報と教師をどう使うかが分岐します。TransFuserは画像とLiDARの特徴間attention、RoachはRLで学んだexpertからの模倣、World on Railsは記録ログから扱いやすい非反応型世界を仮定した価値学習を追求します。RLとILは排他的ではなく、RL teacher→IL studentという組合せがあります。TransFuser、Roach、World on Rails

2022年から2023年：MILEは映像から潜在状態の時間発展と運転方策を学びます。一方UniADは複数の認識・予測タスクを計画へ結び付け、VADはベクトル化された場面表現を使います。どちらも「中間表現を全部捨てる」という単純な進化ではありません。TransFuser誌面拡張は同一研究系統として扱い、初回版と別々に論文数を水増ししません。MILE、UniAD、VAD、TransFuser公式の版説明

2024年から2025年：モデル規模の拡張に加え、評価と推論コストが主要な設計軸になります。NAVSIMは実データと非反応型simulationを組み合わせ、単純な軌道誤差では捉えにくい計画性能を測ります。DriveLMは知覚・予測・計画を関係付けた質問応答を扱い、Think2Driveはlatent world model内でRLを進めます。DiffusionDriveは候補軌道分布を扱いながら反復生成を短縮し、DriveTransformerは過去のtask queryを再利用するstreaming設計を採ります。NAVSIM、DriveLM、Think2Drive、DiffusionDrive、DriveTransformer

2026年10月2日まで：世界モデルとfoundation modelを、車上方策だけでなく教師・合成データ・評価環境にも使う動きがあります。Waymoは2026年2月、cameraとLiDARを生成する世界モデルを公式発表しました。NVIDIAは8月のAlpamayo 2 Super発表で、軌道、言語的説明、meta-action、自動ラベルなどの用途を説明しています。これらは企業による能力・提供形態の発表です。本稿では一般的な安全性、他社比の優位、E2E Liteでの再現性の証明には使いません。Waymo公式、NVIDIA公式

仕組みを共通言語で読む

IL：観測oと経路条件gから、teacherの軌道τを近似するのが基本形です。LBC = E[ℓ(πθ(o,g), τexpert)]。この式が小さくなるのは収集済みデータ上の誤差です。方策自身が少し外れた状態へ入った後の回復は、別のデータ分布の問題になります。データ量だけでなく、停止、旋回、接近、回復をどれだけ含むかを確認します。

RL：J(θ) = E[Σγtr(st,at)]という長期目的を最大化します。問題は報酬設計、探索、sample cost、安全制約です。シミュレータの特権状態でRLを行うことと、生センサ入力の車上モデルをRL学習することは同じではありません。RoachやThink2Driveを導入候補として読む際には、teacher、student、実行時観測を別図にします。

融合と時系列：空間融合は「同じ時刻の異なるセンサの情報をどう結ぶか」、時間融合は「動きと観測履歴をどう保持するか」です。Self-attentionの基本計算はsoftmax(QKT/√d)V。密なtoken同士を全結合する場合、attention行列はtoken数の二乗で大きくなるため、低解像度化、疎なquery、memoryの制限に意味があります。これは一般的な計算構造からの分析で、特定の実装速度を保証する数式ではありません。

世界モデル：p(zt+1|zt,at)を学ぶ場合、行動に応じた未来を考えることができます。ただし、予測画像が自然に見えることと、車両運動・接触・他車の反応が正しいことは別です。MILEのような方策学習の内部状態、Think2DriveのRL用環境、Waymo発表のセンサsimulationは役割が異なります。MILE、Think2Drive

Foundation model：大規模事前学習の表現、言語、生成能力を再利用する分類です。「world model」と同義ではありません。VLMが正しく説明できても、操作に必要な幾何、latency、分布外時の停止判断が正しいとは限りません。言語説明の評価、軌道品質、実際の閉ループ行動は別々に検証します。DriveLM、Alpamayo-R1

強みと限界を比較する

センサから軌道までの直接ILは構成を追いやすい一方、成功軌道だけでは回復行動を学びにくい設計です。明示的な中間タスクは診断と補助教師に役立つ一方、ラベル生成と複数損失の調整が増えます。多候補生成は複数の正解を表現できますが、候補を安全に選ぶscoreや制御制約は別途必要です。world modelは反実仮想を扱える可能性を持ちますが、model errorを方策が利用してしまう危険があります。以上は各構成からの工学的推論で、全手法に共通する実験結果ではありません。

故障を「モデルが弱い」でまとめず、認識欠落、時間ずれ、進路条件の曖昧さ、教師の偏り、controller不整合、計算deadline超過へ分けると、再学習が必要な問題と、入出力契約を直す問題を切り分けられます。

E2E Lite TransFuserで検討する順序

監査済み資料との差分：既存サイトのmain説明ではCamera・2D LaserScan・ego/historyから時刻付きTimePathを出力し、制御はモデル外です。原著TransFuserの3D LiDAR、単一時刻入力、goal条件付きdecoderとは異なります。対象commitのTimePathV1、time backbone、teacher分離などのテストsourceを確認しています。今回の確認はコードとテストsourceの閲覧で、新たな実行検証ではありません。既存のteacher分離実装を保ち、以下の追加調査候補とは分けます。

  1. 最優先の候補：センサを使わないego/history-only基準と、Camera-only、LaserScan-only、fusionの比較設計。必要なのは同じrun/scenario split、同じhead、同じ学習予算。各条件を再学習して初めてfusionの寄与を比較できます。入力をゼロにするだけのテストは分布外stress testとして分けます。
  2. 次の候補：旋回・停止・近接・復帰区間の分布を記録し、teacher由来、測定値、推定値を明示するデータカード。コード変更候補はdataset metadataと評価集計であり、運転controllerの変更は不要です。
  3. その後の候補：時間融合の長さやquery数を一要因ずつ変える。履歴同期、ego-motion補償、欠測maskが必要で、過去frameの並べ方だけでは正しい時間モデルになりません。VRAM、遅延、保持状態のreset条件を測定します。
  4. 後順位の候補：VLM teacherやworld model。事前に、追加ラベルの正確性、ライセンス、入力センサ差、教師実行費用、蒸留先の遅延上限を確認します。まずoffline分析用teacherとして費用対効果を調べる、という提案であり導入決定ではありません。

検証ゲート：①shape・単位・時刻・teacher漏洩のテスト、②未学習runでのoffline slice、③同一route・seed・controllerでの反復simulation、④衝突・逸脱・停止理由・完走率・遅延の同時確認。offline改善だけで速度を上げたり安全監視を外したりしません。本調査で学習、制御変更、走行実験は行っていません。

今回の範囲と次に埋める穴

本稿は代表研究の設計比較です。2026年論文の全数抽出、全企業の非公開stackの推定、実車の安全性比較は未実施です。次の深掘り候補は、原著TransFuserの再現契約、BCの分布ずれと回復データ、評価器差分、teacher→studentの情報制約です。企業発表は独立した実験・モデルカードと結び付くまで別の証拠区分を保ちます。
