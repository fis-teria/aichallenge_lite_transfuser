BayesRace：車両モデルの残差を学び、MPCの予測を補う

Achin Jain, Matthew O’Kelly, Pratik Chaudhari, Manfred Morari

同じ経路を追っても、旋回や制動で予測と実際の動きがずれると、MPCが選んだ操作は期待どおりに働きません。BayesRaceは単純な車両モデルを残し、過去の走行から学んだ残差で予測を補います。何を学ぶのか、公開コードのどこを再確認すべきか、現行TimePathへ接続するには何が足りないかを整理します。

対象はBayesRace: Learning to race autonomously using prior experience。CoRL 2020の研究で、PMLRの書誌年は2021です。arXiv初稿は2020-05-10、確認版v2は2020-11-15。2026-10-08に採択本文全12頁・付録・図表、arXiv v2と著者実装の固定commit 0a23cf9を確認しました。以下は文献とコードの静的調査です。本プロジェクトへの実装、著者結果の追試、学習・走行試験は行っていません。

1. 学習するのは、次の状態の予測誤差

横滑りまで表す動的モデルでは、路面やタイヤに合わせた同定が必要です。原著は、縦・横速度とヨーレートを含む拡張運動学モデルを土台にし、実際の次状態との差をGP（Gaussian Process）で学びます。タイヤ係数を直接推定する手法でも、画像から操作を出すE2E方策でもありません。レーシングラインをBayesian optimizationで作る処理は、この残差学習とは別の段階です。原著§3、§4

2. 状態・操作・GPの入力を分ける

状態は x = [X, Y, ψ, vₓ, vᵧ, ω, δ]。位置X・Yはm、姿勢ψと操舵δはrad、縦・横速度はm/s、ヨーレートωはrad/sです。操作は u = [d, δ̇] で、dはPWM duty、δ̇は操舵角速度です。原著のΔδはTable 1でδ̇として使われます。操舵角そのものや加速度指令と同じ入力に読み替えません。

式1　記事用に添字を簡略化した予測補正
関係意味と境界
eₖ = xk+1 − fkin(xₖ, uₖ)同じ初期状態と操作から、一段先の差を学習する。連続時間の加速度残差とは単位が違う。
zₖ = [vₓ, vᵧ, ω, δ, d, δ̇]GPの特徴は6成分。三つのGPがvₓ・vᵧ・ωの残差を出す。位置を直接GPで予測する構成ではない。
xk+1 = fkin(xₖ, uₖ) + B μGP(zₖ)Bは三つの補正を7状態へ配置する行列。MPCにはGPの平均を使う。

出典：§4.2、式3–6。平均で不確実性を置き換えるため、GPの予測区間が描かれていることからchance constraintや衝突確率の保証は導けません。

式の不一致：採択本文Table 1の拡張運動学モデルは ω̇ = (δ̇vₓ + δv̇ₓ) / (lf + lr)。一方、固定版のkinematic6.pyは数値モデルとCasADiモデルの双方で (δ̇vₓ + δv̇ₓ) × (lf + lr) です。論文どおりの式とは確認できません。修正して図の結果を再現できるか、保存済みデータ・モデルがどの式で作られたかは未確認です。

離散化も別：残差用の予測生成はRunge–Kutta積分を呼びますが、gpmpc.pyの状態遷移は前進Eulerの x + Ts·f + e。本記事の解析として、GPだけを別の刻みや積分法へ移すと、残差の意味も変わります。またPWMモデルは駆動係数Cm1・Cm2を使うため、「幾何と質量だけで全入力モデルが不要」とは扱えません。

6. 現行TimePathへ接続する前に必要なこと

現行コードの事実：公開系統 358623cのTimePathV1は観測時のbase_link座標で30点の未来XY（0.1〜3.0 s）を出します。区間弦長の速度ノルムは、符号付きvₓ・vᵧやωとは別です。参照空間MPPIは4係数の横オフセット・曲率候補から経路を作り、静的占有を検査します。これはBayesRaceの7状態を予測するNMPCとは異なります。

導入候補：TimePathを参照経路にし、下流で車両状態を予測する制御器を定義する接続は考えられます。ただし現行の基本追従器は操舵角と加速度を出します。BayesRaceのPWM duty・操舵角速度とは単位も駆動系も違い、公開コードの入力をそのままつなげません。以下は未実装の検証案です。

  1. 状態と適用時刻をそろえる：指令値・実舵角・車速・姿勢変化を区別し、通信と駆動応答の遅延を含める。診断用の情報を無断で推論入力へ変えない。
  2. まず基準モデルを検査する：単位、ヨーレート式、入力変換、積分法を固定する。低速直進で合うだけで限界旋回のモデルが得られたとは扱わない。
  3. 走行単位で学習と評価を分ける：隣接サンプルをランダム分割するだけでなく、別走行・別速度・別路面の一段／多段残差を測る。GPの分散と実際の誤差の対応も確認する。
  4. 同条件の制御比較にする：参照経路、速度上限、車体形状、停止監視、占有処理、計算予算を固定し、補正の有無を比較する。不要停止・接触・最大逸脱・slack・期限超過を記録する。
  5. 計算全体を測る：センサ入力から実際の指令適用までのp50/p95/p99、最大値、解なし時の処理を測る。GP学習時間、モデル更新、MPC solve、GPU利用の効果を混ぜない。

本プロジェクトの過去の5 km/h・AWSIM静止箱試験は、記事に記載した限定条件の結果です。今回の文献更新で高速走行・タイヤ同定・BayesRaceの性能を確認したことにはなりません。
