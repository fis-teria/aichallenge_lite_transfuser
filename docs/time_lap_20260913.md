# TimePath B0: 1周を目指すAWSIM試験

## 実行目的と現在位置

ユーザー依頼: 「次は完走目指して」「テスト時はRvizにE2Eが出力した走行経路」。
指定ホスト `graneple@192.168.3.10`、固定5km/h、通常のAutoware RVizを継続する。
前回 [trial05](time_fixed_5kmh_20260913.md) は10秒/11.238m、停止確認済み。
開始commit `6b1450e995204ecbf4d2a9431f387a71efb3eb8a`、Windows/WSL clean。

最初の阻害要因は10秒の固定終了条件で、周回を実行できないこと。
実測ホストの参考中心線は最終s=367.026m＋閉路接続約0.95m。4.62km/hなら
約5分が見積もり。中心線は時間見積もりだけに使用し、モデル/PPへの入力にはしない。

## 今回必要な変更

- `bounded_10s` を保全し、`one_lap` 実行設定を追加。走行最大600sim秒/600wall秒、
  起動・停止・終了処理を含む全体上限720wall秒。新しい周回依頼に対応する有限枠であり、
  前回の120秒以内の短時間試験として扱わない。外側TERM/KILL監視を維持する。
- AWSIMの未改変LapCountログで順序付き区間通過と `Lap completed` を検出し、
  最初の1周で制動要求。画面のLap 1や出発点への近接を完走とみなさない。
- 周回中の低速停滞5sim秒で終了要求。通常のセンサ/時計/経路/停止距離/過速度/権限監視は維持。
- 停止要求は専有ディレクトリ内でatomic公開し、制御側はrun IDを確認して保持する。
- 通常RVizの標準Pathを有効化し `/visualization/time_path/raw_path` の生30点を表示。
  起動時の受信先と走行中画面を記録する。推論・XY・座標変換・操舵/加速度制御・重みは変更しない。

所有層は周回試験の終了・監視・可視化。モデルの見かけの成功を作る経路修正は行わない。
既存JudgeLogを依存のない共通部へ移して再利用し、旧Tinyの判定結果を保全する。
変更しなければ周回と完走判定が不可能。旧設定指定で戻せ、判定・時間境界・停止要求・
RViz表示の回帰テストとWSL全体テストで個別に確認できる。

モデルはTimePathV1 B0 command history OFF、epoch10、FP32、checkpoint SHA256
`e857db4b67d3d9f6a77c2865cfc1fa53e9903e7a1d2d8a371407fbe009a1a44f`。
操舵はPure Pursuit、target 5/3.6m/s、overspeed 6/3.6m/s、加速度±1m/s^2。
全30点の時間軌道、observation時刻、map/base_link/rear_axle、teacher/input分離を維持。

成功判定: 通常RVizでE2E経路を表示した実行で、順序付きjudge1周＋実測停止確認。
未完走なら最初の阻害要因・場所・生予測・制御理由をWSLで評価する。
新規run IDを1度だけ消費し、自動再試行しない。異常なら停止・証拠保全して原因を分類する。
旧ホストcheckoutの既存変更、39個の履歴Compose、旧データ/重み/試験を保全。

現在: 有限周回設定、judge移設、停止要求・停滞監視、RViz受信確認、任意試験長の
記録評価を実装。次はWSLテスト・旧trial05再計算、同一ソースのROSビルドと接続確認。

containerへそのまま渡さない。実行前にログ存在を確認し、判定記録なしで駆動しない。
