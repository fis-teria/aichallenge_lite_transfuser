### 診断結果と次の判断

上記診断をcommit `e5718956e0044e0df4f022f5dceaa3a21c806628` のnative WSLで実行し、
保存した最初の `STOPPING_CORRIDOR_OCCUPIED` を既存 `check_scan` で完全再現した。
投影の既知解・端点・重複点・全点重複時拒否・90度座標変換のsmokeもPASS。
コード/設定/重みを変更する再試験は追加していない。

| 確認対象 | lap07実測・保存記録からの計算 |
|---|---|
| 計測速度 | 1.238123m/s（4.457km/h）。目標は5km/hで実速度固定ではない |
| scan監視のclearance / 必要距離 | 1.784845m / 1.785537m。0.000692m下回る |
| 最初の拒否ray | index464、range2.279951m、左向き0.376991rad |
| scanの時刻差 / planの時刻差 | 0.014025s / 0.205s |
| 判定点（現在base_linkへの診断変換） | 前3.745894m、左0.842468m |
| E2E現在基準reference終点 | 前3.255977m、右0.400401m |
| 判定点からE2E折れ線まで | 1.335943m。最近点は**軌道の終点** |
| 保存plan単体のPP計算 | 右操舵-0.066301rad、形状チェック通過 |
| 参考中心線との符号付き線分距離 | 開始時左1.112623m、拒否時左1.093046m |

確定した停止原因は、右へ曲がるE2E予測の有無によらず、**車両前方の直線矩形**へ
左前方のLiDAR点が入ったこと。形状の折返しやstale-planが最初の拒否ではない。
曲がる経路を使わない監視が早期停止した可能性がある。ただし判定点は予測の終点より
前にあり、折れ線への点距離は車体の通過余裕ではない。これを「誤検出確定」や
「このまま通過可能」とは扱えない。0.7mmの差を理由にしきい値を緩める変更もしない。

scanは全rayをheader時刻の姿勢で変換した診断で、各ray時刻の補正や動的TF、車体全体の
swept footprintを検証していない。保存planのidentity・時刻姿勢・数学計算は確認したが、
このcycleはscan拒否が先なのでruntimeのplan受信時刻/graph admission済みとは扱わない。
中心線は教師/義務付けられた走行線ではなく、開始時点でも約1.1m離れていた。
この値だけで「今回1m逸脱した」「学習データ不足」とは結論しない。

次に必要な判断・推奨範囲は、Safety Supervisorの**曲がる際の車体通過範囲を含む診断**。
まず記録上で、実操舵と制動中の車体全体、外側の張り出し、LiDARの未観測範囲を扱い、
直線判定との差を検証する。監視を置き換える場合も、未観測/時刻不整合/停止距離不足の
拒否を維持できる根拠と回帰テストが先に必要。速度・安全余裕の緩和や、地図経路の
モデルへの代入で完走扱いにしない。現在は診断結果を整理して実行を終了した状態。
