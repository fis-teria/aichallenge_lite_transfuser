# 教師・予測・実走の停止余裕比較

目的は turn16 の路端側余裕不足を教師、予測、追従のどこで生じたか切り分けること。
学習・checkpoint 選び直し・監視変更・新しい実走は行わない。

## 評価前に固定する条件

- 5km/h 設定の train 6周 (01,02,04,05,07,09) と validation 2周 (03,06)。
  test のデータ本体は読まない。run 分離を維持する。
- 停止時の記録 map pose に最も近い同方向の教師地点を中心とし、教師の記録
  走行距離で前後12mを対象にする。推定自己位置による比較で、真値とは扱わない。
- validation は学習時と同じ cache 順序の既存 command_off FP32 予測を使い、
  同一観測・同一 LiDAR に正解30点と予測30点を入れる。入力有効かつ全点教師ありを対象。
- 既存 Pure Pursuit (stopping_preview_v1, awsim_understeer_v1) を同じ条件で使用する。
  計算の比較は観測時刻の新鮮な計画を仮定し、実測舵角を measured/previous、
  計算した名目物理舵角を issued に用いる。lead/通信遅延/新しい車体運動の再現ではない。
- 実測速度での計算に加えて turn16 拒否時の1.285883665m/sに正規化する。
  正規化では実測 yaw/v と後輪横速度を保持する。実際の教師走行結果ではない。
- 車体 [-0.510,1.984]m × ±0.85m、停止移動距離 0.4+0.5v+v²/2m、
  曲率区間と横移動上限の囲みは現行監視と同じ。指標は ray に沿う観測距離と
  必要距離の差であり、衝突距離や全周囲の自由空間証明ではない。
- raw bag、使用する cache label/anchor、既存予測、実走記録を hash で記録・照合する。
  欠損、時刻の重複、姿勢の補間不成立、監視契約外は除外理由と分母を残す。

教師収集先 .13 と実走先 .10 の現行 scene/DLL/YAML はファイルhashが異なる。
記録中の TF、収集起動引数、センサ配置と車体パラメータを確認し、現在の資産照合を
収集当日の完全な同一性証明と混同しない。異なる場合は環境差を残して報告する。

編集・Git正本はWindows、評価とpytestはnative WSLのworktree lock内で行う。
結果と再現コマンドは評価後に追記する。
