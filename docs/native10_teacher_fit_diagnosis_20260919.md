# LiDAR教師が回避できてもE2Eが接触する原因の確認

**教師走行に回避があることと、その判断をE2Eが学べたことは別である。今回の新モデルでは、採用後の場面の偏りと、学習入力上でも教師軌道を再現し切れていないことを確認した。**

教師契約は`perception=LIDAR_V2X_SURFACE_EXISTING_MARGIN`、`native_v2x_role=EVALUATION_ONLY`。
教師はLiDAR由来の物体位置を使ってMPPIで回避する。学生へのオンラインの指示・更新ではなく、
保存した画像・LiDAR・車両状態から将来30点のXYを模倣学習する構成である。
教師が持つ物体位置表現、基準経路、衝突判定の処理自体は学生にコピーされない。

教師manifest・anchor/NPZのハッシュ、442件の一意性、[442,30,2]の有限値・順序を確認した。
新規推論・学習や設定変更は実施していない。

## 採用場面と学習方法

- 旧338窓、新104窓のどちらも、既存の配置監査で「前方0～6m・横±1m以内」の採用窓が0件。
  教師が早めに避けることと、品質選別によって接近中の窓が保留になることが関係する。
  この矩形条件は分布調査用で、衝突判定ではない。
- 新104窓の選別では保留568窓、うち547窓にscan/map照合不一致の理由がある。
  点数不足・角度支持不足は0件。原因を調べずに閾値を緩める根拠にはならない。
- native教師は4,420/65,028提示、約6.80%。コーン文脈は3,260提示、約5.01%。
  通常・発進・復帰の保持を優先した配分で、回避開始を専用に重点化していない。
- native窓への損失は基本のXY L1。既存の操舵相当・遠方横位置の補助損失は
  `codex-time-recovery-*`の対象anchor専用で、native障害物窓には適用されない。
- 観測速度は保存しているが、今回は速度・停止・行動モードのHeadは学習していない。
  実行側の速度は既存の曲率・利用可能距離によるPP側方針であり、教師MPPIの減速判断を
  そのまま再現する構成ではない。

過去の短期比較では前方接近の重点化と補助損失に教師適合の改善が見られた一方、
通常・復帰保持を満たさず、実際の失敗入力でも回避への変化は数cmだった。
今回、効果が確定した設定としてその診断条件を採用したわけではない。
これらからデータ配分・目的関数が原因候補になるが、モデル容量の限界や唯一の主因とは断定しない。

## 統合対象の不足

以前に選別・再現確認済みの`front_curated_v1`の259窓（コーン周辺97・通常162）は、
今回の学習manifestに含まれていなかった。4runすべてが今回の13runと非重複であることを確認。
今回の`native_sources`は`curated_xy_speed_v3`338窓と`collect10_curated_v1`104窓だけだった。

これは今後統合対象を整理すべき不足。ただし259窓も正面近接の矩形条件は0件で、
単に足せば今回の接触が解消すると断定できない。箱試行の採用分は通常走行であり、
箱近傍の回避教師ではない。この調査では再学習・データ追加を行っていない。

## 実走・制御との対応と次の優先事項

新モデル10km/hの実走では、コーン・箱とも接触直前は3秒先約8m、横位置約±0.1mの
直進に近い予測だった。速度急落より前は目標10km/h、加速指令が正。
コーンの運動不整合・先読み不成立・進行停滞による停止はその後に起きた。
したがって、PPが十分な回避軌道を曲がり切れなかったことだけでは今回を説明できない。

1. 未統合259窓を含め、検知前・検知・回避開始・側方通過・復帰の採用状況をrun単位で整理する。
2. 品質照合で回避開始区間が保留になる原因を調べ、原本と教師の対応を保って選別を直す。
3. 回避開始を重点化し、native教師の横方向・PP操舵相当の誤差も評価/学習する比較を、
   既存の通常・復帰保持と両立する配分で実施する。まず既知教師を再現できるか確認する。
4. 未知シナリオと実走接近状態に対して、必要な回避幅が出るかを別に評価する。

この順序なら「教師が回避できるのに、どこで学生へ伝わらなくなったか」を追える。
収集量だけ増やすことや、制御パラメータだけ変更することを先に結論にしない。
