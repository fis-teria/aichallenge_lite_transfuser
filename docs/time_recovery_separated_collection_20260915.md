# 通常操舵を基準に外乱区間とPP復帰区間を分ける収集

前回の加算方式では、外乱中にもPPが逆操舵していた。新しい収集専用
`nominal_guide_then_pp_v1` は、実測通常周回の進捗に対応する操舵を基準にする。
推論入力やモデル、実行時のE2E制御は変更しない。

- ROS入力操舵の外乱は左右0.1 rad。0.25 s立ち上げ、1 s保持、0.25 s解除。
- 基準操舵も同じ割合で通常操舵へ移し、解除時に現在のPPへ戻す。
  コーナーでも開始時の操舵を固定せず、現在のコース進捗で補間する。
- 収集目標への到達による解除は開始1.25 s以降。横25 cm、向き4度、速度、
  進捗、壁時計の上限と独立した停止領域監視は先に適用する。
- 解除のブレンド全体を`hold`として除外し、純粋なPPへ戻った出版境界+150 ms
  以後の実測未来0.1～3 sのみを教師候補にする。新方式の制御メタデータも検証する。
- 従来方式は既定値として維持する。旧収集の保留状態・記録・予算を変更しない。

新しい有限計画はS00単独の左右2周を先行し、その結果を確認してから既存の
seed=915110で選んだ追加10地点の左右へ進む。最大10周・22イベント、各周1～3イベント。
S00の狙いは教師経路進捗119～120 mに横ずれと復帰が重なること。
外乱開始点と最大横ずれの位置を別々に報告する。通常RVizには発生位置のマーカーを出す。
実行前に通常2周の操舵・観測・実行環境をハッシュで照合する。

判定は実出版の操舵と通常操舵との差、実測操舵、横ずれ、向き、解除理由、
PP復帰確認、完周・通常停止、bag/センサ/教師の検証を分けて行う。
境界による短縮を「1秒保持成功」に数えず、失敗データも保全する。
同じ停止地点を試験のために危険な旧停止位置へ直接移動する操作は行わない。

実行コマンド（Windows編集・コミット後、同一コミットのWSL同期先）:

```sh
tools/with_wsl_training_lock.sh env PYTHONPATH=src .venv/bin/python -m pytest -q
```
