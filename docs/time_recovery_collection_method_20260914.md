# 外向きのずれから戻る時間軌道教師の収集案

2026-09-14。検討・設計の成果物。収集用runtimeの変更、新規AWSIM走行、再学習は今回未実施。
実行先は`graneple@192.168.3.10`、変換・検証・学習はnative WSLを使う。

推奨は、**通常経路をAIチャレンジ環境の教師PPに常時追わせ、小さく滑らかな操舵外乱を短時間だけ加え、
解除後の実測復帰を教師にする方式**。その後、学習モデル自身の小さなずれから教師PPへ
引き継ぐ方式を追加する。位置・向きが戻り切る前の状態を学習対象に含める。

ユーザー提示のTransFuser解説を[一次資料と照合](transfuser_recovery_source_review_20260914.md)した。
角度拡張・微小操舵ノイズ・waypointからのPIDという説明は確認できるが、
回転拡張は実際に車体をずらして復帰した時間軌道の代わりにはならない。
本案では実測復帰を優先し、角度拡張は成立条件を確認した後の比較実験に置く。

## 今回埋めたい差

[前回の実測監査](time_corner_recovery_coverage_20260914.md)では、新規118アンカーは
左右各1走行から得られ、横ずれ最大約16.5cm、向き差約±2.3度、実測3.31〜3.42km/h。
ずれと角度が十分ある60件は全て元の経路へ向いた組合せだった。
失敗直前5秒は右35〜112cm、外向き3.2〜7.9度、約4.58km/h。

最初の狙いは、1m外れた状態を作ることではなく、ずれが小さいうちに外向きの運動を
止めて戻す教師を得ること。既存の20cm教師は戻る途中や低い実測速度帯の資料として保全する。
これらの差だけで、モデル失敗の原因がデータのみだと断定しない。

## 方式の比較

| 方式 | 得られるもの | 今回の扱い |
|---|---|---|
| 事前に寄せて戻る固定経路 | 再現しやすい横ずれと復帰 | 既存方式を補助に使う。PPの先読みで採用開始前に向き直りやすい |
| 通常PP＋短い操舵外乱＋解除 | 外向きの位置・向き・操舵履歴からの復帰 | 最初に実装。経路の読替えや別の最終指令発行元が不要 |
| E2Eを短区間走らせ、早期に教師PPへ引継ぎ | 学習モデルが実際に訪れる状態からの復帰 | 外乱方式の成立と再学習を確認してから追加。引継ぎ時刻と教師の準備を厳密に管理 |
| 物理的な開始位置/yawを変更 | 停止から始まる位置・角度の組合せ | 補助候補。走行中の速度・操舵・履歴は再現せず、角での開始は未検証 |
| センサと教師の整合した角度拡張 | 仮想的な向きに対する幾何的な対応 | 追加比較。横位置・操舵応答・走行履歴の実測を置き換えず、現行単眼系列と時間教師での成立を先に確認 |

教師の制御に外乱を与えて復帰例を集める動機は
[DART論文](https://arxiv.org/abs/1703.09327)を参考にする。ただし本案は有限の操舵パルスと
実測未来XYを使う設計で、DARTの外乱分布最適化やアクション教師をそのまま実装するものではない。
後段のモデル走行からの再収集は
[DAgger論文](https://proceedings.mlr.press/v15/ross11a.html)の、学習方策が訪れる状態に
教師を追加する考えに対応する。介入後の実測軌道を使う本案に、同論文の保証をそのまま適用しない。

TransFuserのノイズはCARLAの正規化操舵へ標準偏差0.001を加える処理であり、
本案のAWSIM操舵入力radや有限パルスとは異なる。
角度拡張を外した影響は最終構成では小さいと論文は報告しているため、
拡張が復帰改善の決め手だと前提にしない。
[公式教師](https://github.com/autonomousvision/transfuser/blob/9d413b2ad2d2d56c112b34a4a799be081800d77f/team_code_autopilot/autopilot.py#L249)、
[論文p.14](https://www.cvlibs.net/publications/Chitta2022PAMI.pdf#page=14)。

## 最初の収集の流れ

```mermaid
flowchart LR
    A[正常PP走行・速度確認] --> B[短い操舵外乱]
    B --> C[外乱を解除]
    C --> D[解除後の実測復帰を記録]
    D --> E[通常走行を継続]
    E --> F[1周＋未来4秒・正常停止]
```

通常の基準経路をPPへ継続して与える。PPは現在の自車状態から常に正常ラインへ戻す指令を計算する。
同じcollectorの最終発行前に外乱を加え、**合成後の指令**を既存の操舵量・操舵速度制限、
停止領域監視、センサ/計算期限確認へ通す。監視通過後に外乱を足す構成にはしない。
解除後は外乱を再投入せず、少なくとも未来3秒、実際には復帰確認まで教師制御を継続する。

現行実装の挿入点は`tools/time_recovery_collector_node.py`の
`bounded_collection_command()`呼出し直前。ここから後段に監視と唯一の最終publisherがある。
経路切替案ではgeneratorの1秒配信周期やPP受信の確認が必要だったが、本方式は通常経路を維持する。
新たな重い経路探索や2回の停止領域計算を制御ループへ入れず、現行100ms判断期限を維持する。

外乱は白色雑音を毎周期振る方式ではなく、開始・終了が滑らかな有限パルスとする。
校正の初期候補はROS操舵入力で0.03〜0.05rad、長さ0.5〜1.0秒程度。
これは車体yawを3度変える指令ではなく、応答を測るための仮値である。
現行AWSIMの定常タイヤ角/入力角の係数は0.6。入力角、実タイヤ角、車体yawを混同しない。
実行する振幅・時間の上限は事前検証で固定し、走行中に未達だからと延長・増幅しない。

外乱解除は、狙った位置・向きの組合せへの到達、位置/向き/進捗の上限、パルス時間上限の
**いずれかが先に起きた時点**で要求する。条件未達でも上限で解除する。
最終角度が制限されて狙いが実現しなかった試行も記録し、成功本数へ数えない。
既存の安全監視が拒否した場合は既存の停止処理を優先する。

通常RVizには通常参照・実走Path・外乱/解除位置を表示する。
後段でE2Eを動かす際は、モデルが出した経路も専用の表示名で出す。
センサは自車1台分を記録する。初期段階では教師PPとcollectorを使い、E2E推論を同時稼働させる必要はない。

## 速度と基準線を先にそろえる

目標は引き続き5/3.6m/s。収集PPの`speed_proportional_gain=1.0`と、
E2E側の`speed_kp=4.0`の差を整合させる。ゲインだけでなく入力速度の取得元・時刻、
加速度の単位・上下限・発行周期、trajectory側速度上限も照合する。
設定値の一致を実測速度の一致と扱わず、まず外乱なしで正常走行2本を確認する。

同じ速度条件でもPPのコーナー軌跡が変わり得るため、新しい通常実走を固定した比較基準にする。
旧r22/r23も併記するが、速度を変えた後の実走を旧基準に無理に合わせない。
位置・向き・速度の条件別評価は同じ元コース進捗で比較する。
暫定の速度整合判定は、対象区間の実測速度中央値の差0.05m/s以内。
この閾値は開始前に固定する案であり、実測5.00km/hの達成を宣言する値ではない。
教師PPがこの速度条件で正常に角を通れなければ、復帰データ収集へ進まず教師制御を切り分ける。

## 教師の開始時刻と除外条件

外乱の開始/解除要求だけでなく、nominal指令ID・stamp、要求外乱、制限後の発行角、
最終command sequence、実際の発行sim stampとmonotonic時刻を記録する。
この対応が失われた区間は教師にしない。現在のdecision時点の`sim_ns`だけを流用しない。

採用の基準は、外乱成分が0となった教師由来の最終指令を発行した境界。
新たな外乱入力の発行が続くramp-down中は除外する。
通信・制御時刻の不確かさは明示した境界余裕に含め、境界より後の最初の有効cameraから採る。
**実測タイヤ角が追いつくことや、車体の向きが戻ることを採用開始条件にしない。**
解除以前の指令による操舵遅れ・車体の運動は復帰初期状態の一部で、実測操舵と過去指令履歴を保持する。
比較対象の現行checkpointは指令履歴OFFなので、保存される履歴とモデルが使用する履歴を分けて記録する。
今回の収集変更と同時に指令履歴ONへ切り替えず、必要なら別の比較にする。
送信境界をAWSIMが指令を物理適用した時刻と呼ばない。古い指令の再送・順序逆転は除外する。

| 時間窓 | 保存 | 正解の扱い |
|---|---|---|
| 外乱開始より前〜外乱中 | 全センサ・実行指令・状態 | 復帰アンカーの過去履歴に残す。外乱が入る未来を正解にしない |
| 外乱解除の境界が不確かな部分 | 同上＋切替記録 | 境界が検証できるまでアンカーを除外 |
| 解除後、まだ外を向いている部分 | 同上 | 最優先の復帰教師。未来0.1〜3.0秒を実測poseから作る |
| 復帰中〜通常ラインへ収束後 | 同上 | 品質判定後に採用。通常走行だけで復帰例を埋め尽くさない |
| 次の外乱、reset、停止介入、センサ異常を跨ぐ未来 | 理由付きで保存 | 復帰教師にしない |

教師は従来どおり`base_link@観測時刻`での実測XY `[30,2]`、間隔0.1秒、単位m。
CSVを未来教師に置換せず、画像/LiDARだけを移動して異なる状態を捏造しない。
入力選択のreceipt freeze 50ms、現在/過去の欠損mask、epoch分離は維持する。
外乱・基準線・復帰phase・位置誤差はteacher/debug専用で、推論入力へ追加しない。

現行`materialize_recovery_run()`と`causal_replay_probe.py`にはphase開始後150msの
一律除外がある。これが外向きの短い時間を捨てていないか、先頭0.5秒の候補と除外理由を監査する。
新方式は実際の発行境界を使う版付きの区間注釈を設け、境界テストで妥当性を確認してから扱いを変更する。
既存データの150ms規則は維持し、新データでも境界が不明なら保守的に除外する。
単一の`intervention_ns`は末尾の停止を遮断するための値なので、外乱解除時刻を代入しない。
そうすると解除後のアンカーも全て遮断してしまう。採否は期間の集合で管理する。

## 狙う状態と本数

状態は新しい正常実走に対する符号付き横ずれ`e_y [m]`、車体向き差`e_psi [rad]`、
実速度`v [m/s]`、実測操舵`delta [rad]`、yaw rate `[rad/s]`で整理する。
`e_y * e_psi > 0`を外向きの組合せとして分類するが、横誤差の時間微分と同一視しない。
外乱振幅でラベルを決めず、**解除後に採用できたアンカーの実測状態**で分類する。

最初は正常2走行＋左2走行＋右2走行の計6走行を方式確認の予算とする。
1走行に問題の角付近の介入を1回だけ置き、前後を含む1周を記録する。
同じ不成立を設定変更なしに反復しない。これは必要データ量を満たす本収集ではない。

方式が成立してから、初回の本収集候補を以下の4条件とする。
いずれも目標5km/h、実測速度整合済み、外向きyaw差2〜4度を狙う。

| 条件 | 採用アンカーで狙う横ずれ | 独立runの初期目安 |
|---|---|---|
| 左へ小さくずれ、左を向く | 左5〜15cm | 6本 |
| 右へ小さくずれ、右を向く | 右5〜15cm | 6本 |
| 左へややずれ、左を向く | 左15〜25cm | 6本 |
| 右へややずれ、右を向く | 右15〜25cm | 6本 |

計24本は収集計画上の初期目安。各条件でtrain 4本、validation 1本、未使用の評価予約1本を
実行前に割り当てる。同一runの全フレーム・切り出し・複製は必ず同じgroupに置く。
予約分は既存testの再分割に使わず、現行train/validation用materializerへ渡さない。
校正・条件調整で見たrunを最終評価へ回さない。同じ走行を複製して独立本数を増やさない。
6本/条件で十分な汎化を保証するものではなく、不足する実測状態の条件だけ後で増やす。

狙った横ずれとyaw差が同時に作れるかは未実証。未達は「未達」として分母に残す。
外向き4〜6度などはこの4条件が成立した後に検討する。
既存の固定経路検査では左右30cm・右40cmが通過し左40cmは不成立だったが、
操舵外乱の通過領域は別途確認する。固定経路の地図通過を新方式の成立証拠に流用しない。

## 採用と効果の判定

正常2走行のばらつきを見て、復帰判定を本収集前に固定する。初期候補は、解除後10秒以内に
`abs(e_y) <= min(0.10m, 解除後ピーク横ずれの50%)`かつ`abs(e_psi) <= 2度`を
1秒維持すること。初期に横ずれが少し増す正しい復帰もあるため、全時刻の単調減少は要求しない。
ピークずれ・復帰時間・監視余裕・操舵飽和を必ず併記する。
条件を満たせない教師走行を、位置を後処理で直して成功扱いにしない。

最初は現行の正常停止・bag close・1周完了のrun採用条件を維持する。
異常終了runの部分救済は別検討に分け、失敗数と除外理由を保全する。
全採用候補の入力と未来30点を監査し、代表候補は元画像/LiDARからtensorと教師を再現する。
独立run数、外向きの有効アンカー数、解除後先頭0.5秒の採用数、条件別欠損率を報告する。

学習後は通常コーナーと復帰条件を分け、WSLの条件別誤差と`.10`のAWSIMを比較する。
教師へ引き継いで完走した走行はE2E完走として数えない。
初回再学習後も足りない状態が残る場合に、E2Eを短区間動かし早期に教師PPへ引き継いで再収集する。
引継ぎ前のE2Eの未来を正解とせず、引継ぎ後に教師制御で観測した未来だけを使う。

追加比較は、同じ初期重み・学習予算・独立評価run・制御設定で、まず既存データと
実測復帰追加を比べる。角度拡張の成立後に拡張単独と併用を追加する。
カメラの有効画角、LiDAR再投影、全履歴の整合、初期運動からの時間軌道の実現性を確認し、
拡張はtrainに限定する。全派生データは元runのgroupを引き継ぐ。
公式の0.5秒間隔の先頭2点を、現行0.1秒間隔の先頭2点へ置き換えて制御を変更しない。

## 容量・実装順

既存運用を継続し、2runごとにbagを閉じてWSLへ転送、全ファイルSHA/サイズ/構造を照合する。
照合後に限定した元データだけを移動済み案内に置き換える。開始直前の空きを再測定する。
通常終了は1周＋未来4秒、停止実測3秒。1試行はsim 30分、wall 31分、outer 33分、bag 2GiB、
ホスト空き10GiB以上の既存上限を維持する。計算負荷の分離と通常RVizも継続する。

過去のbag量から、本収集24本は原本約30〜40GiB、圧縮込み約45〜60GiBの粗い見積もり。
速度・記録時間で変わるので、方式確認6本と作業用コピーを含めWSLに約80GiBを予算化する。
24本分をAWSIMホストへ同時に置かない。十分性や採用数をGBだけで判断しない。

| 順序 | 実装/確認対象 | 完了条件 |
|---|---|---|
| 1 | 収集と評価の速度制御、通常PP走行 | 同じ目標・実測速度帯で正常に角を通る |
| 2 | ROS非依存の外乱状態機械、collectorへの挿入 | 時間/振幅上限、解除優先、NaN、飽和、停止監視の回帰テスト |
| 3 | 指令発行境界の注釈、時間教師の採用処理 | 遅延・順序・欠損・再外乱・epoch・3秒未来境界のテスト。過去履歴を保持 |
| 4 | `.10`で6走行の方式確認とWSL監査 | 外向きの有効な復帰教師が左右で得られる |
| 5 | 条件別の独立run収集、再学習、AWSIM比較 | 未使用runへの改善と通常走行への悪影響を確認 |

編集・Git正本はWindows。実装時はcommit後に`tools/sync_to_wsl.ps1 -CheckOnly`と通常syncを行い、
WSLの`tools/with_wsl_training_lock.sh`経由で`pytest -q`、データ検証、学習を実施する。
新方式の起動コマンドは未実装であり、上記はまだ実行可能な起動手順ではない。
